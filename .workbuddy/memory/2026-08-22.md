## 根除崩溃：QDockWidget 在非 QMainWindow 中是 Qt 未定义行为

- 用户提供 QtCreator Debug Disassembler 截图：崩溃停在 QtWidgets 内部虚函数调用（`callq *disp32(%rax)` via rax=vtable）和 `c2 ret imm16`（__stdcall 函数返回）——典型的**对象 vtable 已损坏或被 delete**。
- 对比"员工能进、管理员崩"差异：aw 是首次 show 触发最剧烈；ew 之前能进纯属运气，迟早也会崩。
- **根因确认**：adminpagewidget.ui / employeepagewidget.ui 的左侧菜单使用 `QDockWidget`，但根 widget 是普通 `QWidget`（不是 `QMainWindow`）。`QDockWidget` 在非 `QMainWindow` 中使用属 Qt 未定义行为——`show()` 时 Qt 内部尝试访问 `QMainWindow::dockWidgetArea()` 之类虚函数，但 QMainWindow 指针为空 → **虚表指针悬空 → 崩溃**。
- **修复**：把两个 .ui 中 `ngtDockWidget` 从 `QDockWidget` 改为 `QWidget`，清理其专属属性 `allowedAreas`（QDockWidget 才有）、`features`；app.qss 中 QDockWidget 样式改用 `QWidget#ngtDockWidget`；删除 cpp 中的 `setFeatures(NoDockWidgetFeatures)` 调用（QWidget 无此方法）。
- **编译验证签名**：第一次编译报 `'class QWidget' has no member named 'setAllowedAreas'`——**完美印证根因**（.ui 中 QDockWidget 专属属性触发了 vtable 调用）。清理属性后编译通过，NexCard.exe 405KB。

## 真正根因：退出主控时删除了欢迎页 → QTimer use-after-free 崩溃

- 用户执行 Release 仍崩溃 → 确认是真实代码 bug（非 Qt Debug 特有问题）。
- **根因分析**：
  - `EmployeePageWidget::on_exitBtn_clicked` / `AdminPageWidget::on_exitBtn_clicked` 遍历 `index >= 0` **删除所有 tab（包括固定的欢迎页 index 0）**，欢迎页内 `timeValueLabel` 等控件被 `deleteLater` 真正删除。

- **修复**：
  - 两个主控 `on_exitBtn_clicked`：`for(int index = totalTab - 1; index >= 1; index--)` **跳过欢迎页 index 0**。
  - 两个主控 `on_pageTabWidget_tabCloseRequested`：`if(index == 0) return;` **禁止关闭欢迎页**。

## 排查"人脸识别不到"（三个根因，已修复）

1. **模型目录位置错误（主因）**：QtCreator 运行时 exe 在 `build-*/debug/`（或 release/）子目录，`applicationDirPath()` 指向子目录；此前 models 只复制到 build 根目录 → 模型加载失败 → worker 静默 return。修复：
   - 复制 models 到 build-*/debug/ 和 build-*/release/（exe 同级）
   - facedetector.cpp 搜索路径增加 `applicationDirPath() + "/../models"`
   - 教训：QtCreator 多配置（debug/release 子目录）下，"复制到 exe 同级"要复制到配置子目录，不是 build 根
2. **NV12 帧格式被丢弃**：DirectShow 摄像头常输出 NV12，cameraframesurface 的 present 无 NV12 分支 → 丢帧 → 无预览无识别。已加 NV12 手动转换（Y plane + 交错 UV）。default 分支加受限 qDebug（前 3 次）便于诊断。
3. **人脸库为空无提示**：worker 比对时库为空只发 matchFailed 的 else 分支（之前 db 空时不发任何信号）→ 界面无反馈。修复：worker 加 qDebug；employeepunchwidget onDatabaseUpdated(count==0) 状态栏提示"请先管理员录入人脸"。

**根因**：Dlib HOG 检测器（`get_frontal_face_detector()`）默认不上采样，对**戴眼镜、表情变化、肤色、非正脸**等情况漏检率较高。1280x720 帧上人脸约占 240px，HOG 应能检测但实测不行。

**修复**：
1. `facedetector.cpp::detectFaces`：`d->detector(mat)` → `d->detector(mat, 1)`（第 2 参数 1 = 上采样一次，内部把图放大 2x 再检测，显著降低漏检率；速度从 ~150ms 增到 ~300ms/帧，可接受）
2. 增加 qDebug 输出实际检测到的人脸数（便于后续排查）
3. 修 `QVector<float>` 跨线程 connect 警告：`main.cpp` 加 `qRegisterMetaType<QVector<float>>("QVector<float>")`

**编译**：Release 通过（NexCard.exe 2.5MB）。

## 升级：MMOD CNN 检测器兜底（HOG 0 检测的根治）

**现象**：HOG 上采样 1 仍 0 张人脸（戴眼镜+1280x720 帧），截图显示画面中清晰人脸。

## 修复：DirectShow 帧上下颠倒导致 HOG/MMOD 双检测器 0 人脸（真正的根因！）

**关键日志**：MMOD 已加载成功，但 HOG→MMOD 兜底仍 0 张；同时用户预览画面是正常的（之前已做 180° 翻转显示）。

**根因**：Windows DirectShow 摄像头 RGB 帧是 **bottom-up（自下而上）存储** → QVideoFrame 转出的 QImage 上下颠倒 → 识别线程收到的是**倒立的人脸** → HOG 和 MMOD 都只能检测正脸，全部 0 张；而预览显示代码做了 mirrored(true,true)（180°）恰好把倒立帧翻正，所以用户看到正常画面——**显示与识别看到的是两个方向**，这是所有检测失败的根本原因。

**修复**：
1. `facerecognitionworker.cpp::processFrame` 开头 `QImage f = frame.mirrored(true, true)`（识别帧与预览一致的 180° 翻转）
2. **崩溃修复**：`QThread: Destroyed while thread is still running` —— 析构里 `wait(2000)` 改 `wait()`（无限等待，processFrame 无阻塞会很快退出），employeepunchwidget/faceregisterdialog 两处
3. 编译：Release 通过（NexCard.exe 2.6MB）

**验证线索**：这次若检测成功，日志应为 `[FaceDetector] 检测到 1 张人脸（输入 1280x720）`（无需再走 MMOD 兜底，HOG 直接命中正立人脸）。

## 性能优化：识别卡顿/录入后未响应

**根因**：检测在 1280x720 全尺寸上执行（HOG 上采样1 约 300ms + MMOD 兜底可能数秒），而摄像头限频仅 120ms（8fps）→ 识别线程处理不过来，QueuedConnection 帧队列无限积压 → CPU 满载、UI 卡顿、识别迟钝；录入确认保存时界面"未响应"。

**修复**：
1. `facedetector.cpp::detectFaces`：输入先缩小到长边 640（FastTransformation），检测速度快约 4 倍（HOG 上采样1 在 640 图上内部等效 1280 检测，效果不变），检测出的矩形按 scale 映射回原图坐标；特征提取仍用原图（准确）。
2. `cameraframesurface.cpp`：限频 120ms → 200ms（5fps，匹配识别能力，不再积压）。
3. `faceregisterdialog.cpp::on_captureBtn_clicked`：确认录入时**先 stopCamera()** 释放识别线程 CPU，再存库+弹窗，杜绝保存瞬间卡死。
