## 一、项目概述

**NexCard（新卡智联）** 是一个基于 **Qt Widgets** 开发的"一卡通"桌面管理系统，面向企业内部场景，将 **员工考勤打卡**、**刷卡消费**、**余额充值** 与 **管理员后台管理** 整合为一套带串口读卡硬件的完整系统。

| 项目 | 内容 |
|------|------|
| 程序名 | NexCard（界面品牌名：**新卡智联**，原 Smart_Card_Pass） |
| 技术栈 | Qt Widgets + Qt SQL + Qt SerialPort，C++11 |
| 数据库 | SQLite 本地单文件（mysql.db），首次运行自动建表 |
| 硬件对接 | 串口 IC 读卡器（默认 COM5，115200, 8N1） |
| 工程文件 | Smart_Card_Pass.pro（含 24 个 .cpp / 24 个 .h / 20 个 .ui） |
| 界面风格 | 浅色主题 + 背景图，树形菜单 + 标签页式工作区 |

**主要功能一览：**

- **员工端**：刷卡登录、查看个人信息、一键打卡（签到/签退自动切换）、浏览商品库并刷卡购买、余额充值
- **管理端**：账号密码登录、管理员注册、串口配置与调试、员工信息管理（查询/修改）、考勤管理（查询/增删改）、商品管理（查询/增删改）
- **公共**：员工自助注册（刷卡 + 填信息）、串口读卡解析

## 二、系统架构（四层结构）

```
┌───────────────────────────────────────────────┐
│  登录层  Widget（QStackedWidget 三页切换）        │
│  刷卡登录 ｜ 管理员登录 ｜ 员工注册                 │
└──────────────┬────────────────────────────────┘
               │ loginOK 信号
┌──────────────▼────────────────────────────────┐
│  主控层  树形菜单(QTreeWidget) + 多标签页(QTabWidget)│
│  AdminPageWidget         EmployeePageWidget    │
└──────┬──────────────────────────┬─────────────┘
       │                          │
┌──────▼──────────┐      ┌────────▼───────────┐
│ 管理员业务模块    │      │ 员工业务模块         │
│ 管理员注册/串口配置│      │ 个人信息/考勤/商品库 │
│ 员工/考勤/商品管理 │      │ 余额充值            │
└──────┬──────────┘      └────────┬───────────┘
       │                          │
┌──────▼──────────┐      ┌────────▼───────────┐
│ MySql 单例      │      │ MySerial 单例       │
│ (SQLite 4张表)  │      │ (串口读卡器 COM5)   │
└─────────────────┘      └────────────────────┘
```

**设计特点：**

1. **单例模式贯穿底层**：`MySql`（数据库）与 `MySerial`（串口）均为全局唯一实例，业务页面直接取单例，避免重复创建连接。
2. **信号槽驱动页面流转**：登录成功发 `loginOK`、主控退出发 `adminExit/employeeExit`，主窗口统一监听切换；读卡器发 `cardIdReceived`，所有需要卡号的页面监听。
3. **标签页懒加载**：主控界面左侧树形菜单点击后才创建对应页面并加入 Tab，关闭时置空指针，避免内存常驻。
4. **登录身份传递**：登录后卡号保存在 `MySerial::cardId` 中，各业务页面通过 `getCardId()` 获取当前登录员工，实现全局会话。

## 四、数据库设计（SQLite，4 张表）

首次运行自动 `CREATE TABLE IF NOT EXISTS`，并写入默认管理员 **root/123456**。

| 表名 | 主键 | 字段 |
|------|------|------|
| `admin` | name | name（用户名）、pwd（密码） |
| `employee` | card | card（卡号）、name、age、sex、department、balance（余额，初始"0"） |
| `attendance` | id 自增 | card、name、department、e_time（打卡时间）、status（签到/签退） |
| `product` | id 自增 | name（商品名）、price（单价）、number（库存）、information（商品信息） |

- 所有查询基本使用 `QSqlQuery` 参数绑定（`bindValue`），有效防注入。
- 考勤按 `card` + 当日时间查询最后一条状态，决定下一次打卡是"签到"还是"签退"。

## 五、核心业务流程

### 1. 员工登录与全局会话
```
串口读卡 → MySerial 正则解析 → cardIdReceived 信号
→ LoginCardWidget 卡号自动填入 → checkCard 校验 → loginOK
→ 主窗口隐藏，EmployeePageWidget 显示（卡号存于 MySerial::cardId）
```

### 2. 打卡签到/签退
```
点击打卡 → 查询该卡今日最后一条状态
  ├─ 无记录 或 最后为"签退" → 本次"签到"
  └─ 最后为"签到" → 本次"签退"
→ insertAttendance 写入流水（含当前时间戳）
```

### 3. 刷卡购买（事务保证一致性）
```
勾选商品 → 确认 → BEGIN TRANSACTION
→ 校验库存>0 → 校验余额≥总额
→ UPDATE employee 扣余额 → 每商品库存-1
→ 任一步失败 ROLLBACK，全部成功 COMMIT
```

### 4. 余额充值
```
输入金额 → 数字合法且>0 校验 → 选择充值方式 → 二次确认 → 余额累加
```

## 六、代码亮点

1. **单例模式**（MySql、MySerial）：全局唯一实例，跨页面共享数据库连接与串口会话。
2. **正则解析串口协议**：`QRegularExpression("([0-9a-fA-F]{1,2}(?:-[0-9a-fA-F]{1,2})+)")` 从读卡器原始数据中稳健提取卡号。
3. **事务处理购买**：BEGIN/COMMIT/ROLLBACK 保证扣款与库存变更原子性。
4. **参数化 SQL**：绝大多数 SQL 使用 bindValue，避免字符串拼接注入风险。
5. **懒加载标签页 + 倒序清理**：主控 Tab 关闭/退出时倒序遍历删除，避免索引错乱。
6. **界面友好性**：所有关键操作均有校验提示与二次确认弹窗，表格列自动铺满、时间戳日志滚动。

## 七、潜在问题与改进建议

| 级别 | 问题 | 建议 |
|------|------|------|
| 安全 | 管理员密码明文存储（默认 root/123456） | 引入哈希（如 QCryptographicHash SHA-256 加盐） |
| 安全 | 部分 SQL 存在字符串拼接（如 `WHERE id IN (...)`） | 改为逐条参数绑定或 QVariantList 批量绑定 |
| 设计 | 数值字段（balance/price/number）用 TEXT 存储 | 改为 REAL/INTEGER，减少转换与精度问题 |
| 会话 | 登录身份依赖全局 `MySerial::cardId`，换卡后旧页面数据可能串号 | 登录时保存身份到会话对象/参数传入，或用 QSignalMapper 按页面传递 |
| 硬编码 | 串口默认 COM5 硬编码在 `initSerialProt()` | 读取配置文件或注册表记忆上次选择 |
| 内存 | `adminofemployee.cpp` 中 `new AdminOFSetEmp` 未设置 WA_DeleteOnClose，关闭窗口可能泄漏 | 统一 `setAttribute(Qt::WA_DeleteOnClose)` 或父对象接管 |
| 健壮性 | 员工购买后余额显示、考勤签到状态依赖全局变量 | 页面刷新时重新查询数据库而非缓存 |
| 代码整洁 | refill/userpagewidget 空壳文件未清理 | 删除遗留文件，res 中未引用图片清理 |
