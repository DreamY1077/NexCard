# 人脸识别打卡功能 · 实现方案与流程

> 项目：NexCard（新卡智联）企业一卡通考勤系统
> 目标：在员工端"考勤打卡"界面（当前为占位页）实现人脸识别打卡，复用已有考勤规则（签到/迟到/早退/签退时段判断）与打卡去重逻辑。

---

## 一、技术选型

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| **方案 A：本地 OpenCV + Dlib** | 离线可用、免费、无隐私外泄 | 需编译/配置依赖、精度受光线角度影响 | 局域网/离线环境，推荐 |
| **方案 B：云 API（百度/腾讯云人脸识别）** | 精度高、活体检测成熟、开发量小 | 需联网、按次计费、人脸数据上传云端 | 有公网与预算 |
| **方案 C：混合（本地检测 + 云比对）** | 灵活 | 复杂 | 大企业 |

**推荐：方案 A（Dlib + OpenCV 本地实现）**，理由：
1. 本项目为课程/演示项目，离线可用最重要
2. 人脸数据不离开本机，隐私安全
3. Qt + MinGW 可静态链接 OpenCV/Dlib 库

### 依赖库
- **OpenCV 4.x**（摄像头采集 `VideoCapture`、图像预处理、画框显示）
- **Dlib 19.x**（人脸检测 HOG + 128 维人脸特征提取 `get_frontal_face_detector` / `face_recognition_model_v1`）
- **SQLite**（已有，存人脸特征 BLOB）

## 三、数据库设计（新增 1 张表）

```sql
-- 员工人脸特征表（员工注册时采集入库）
CREATE TABLE IF NOT EXISTS face_info(
    card     TEXT NOT NULL PRIMARY KEY,      -- 员工卡号（关联 employee 表）
    name     TEXT NOT NULL,                  -- 姓名（冗余，便于显示）
    feature  BLOB NOT NULL,                  -- Dlib 128 维特征（float32 × 128）
    reg_time TEXT NOT NULL                   -- 录入时间
);
```

- `feature` 列：将 128 个 `float`（Dlib `matrix<0,1>`）序列化为字节存入 BLOB，读取时反序列化还原
- 员工被删除时同步删除 `face_info` 记录（可选）

## 四、功能模块设计

### 1. 人脸注册（管理员端，新增"人脸录入"功能）
```
管理员 → 员工信息管理 → 选中员工 → 人脸录入
流程：
1. 打开摄像头实时预览
2. 检测到人脸（且清晰：模糊度/尺寸达标）→ 截取当前帧
3. Dlib 提取 128 维特征
4. 写入 face_info 表（card, name, feature, reg_time）
5. 提示"人脸录入成功"
```
> 可在现有 `AdminOfSetEmp`（员工信息修改）对话框里加"录入人脸"按钮，或单独做人脸录入界面。

### 2. 打卡识别（员工端"考勤打卡"界面）
```
1. 点击"开始打卡" → 打开摄像头 → QLabel 实时显示视频帧
2. 每帧检测人脸 → 画框标定
3. 检测到清晰人脸 → 提取 128 维特征
4. 与 face_info 表中所有记录比对（欧氏距离）
   - 最小距离 < 阈值（建议 0.45~0.55，可调）→ 识别成功 → 得到 card
   - 否则 → 提示"未识别，请正对摄像头"
5. 识别成功 → 调用**现有打卡逻辑**：
   - MySql::getAttendanceRule() 判断当前时段（签到/迟到/早退/签退/未开放）
   - 当天去重（getTodayAttendanceStatus）
   - insertAttendance(card, name, dept, status)
6. 显示打卡结果 → 自动关闭摄像头
```

### 3. 线程模型（避免卡 UI）
- 摄像头采集 + 人脸检测 + 特征提取放**工作线程**（QThread / QtConcurrent）
- 每帧处理完通过信号发回 UI 线程更新 QLabel（QImage → QPixmap）
- 避免阻塞主界面，保证流畅

## 五、Qt 集成关键点

```cpp
// .pro 中链接依赖
LIBS += -lopencv_core -lopencv_imgproc -lopencv_highgui -lopencv_videoio
        -ldlib

// 摄像头打开
cv::VideoCapture cap(0);            // 0 = 默认摄像头
cap.read(frame);                    // 读取帧

// Dlib 人脸检测
dlib::frontal_face_detector detector = dlib::get_frontal_face_detector();
std::vector<dlib::rectangle> faces = detector(img);

// 特征提取
dlib::shape_predictor sp;           // shape_predictor_68_face_landmarks.dat
dlib::face_recognition_model_v1 model;  // dlib_face_recognition_resnet_model_v1.dat
dlib::matrix<float,0,1> descriptor = model.compute_face_descriptor(img, shape);

// 特征比对（欧氏距离）
double dist = dlib::length(descriptor - dbDescriptor);
if(dist < threshold) → 匹配
```

**必须打包的模型文件**（放在 exe 同级 models/ 目录）：
- `shape_predictor_68_face_landmarks.dat`（约 60MB，人脸关键点）
- `dlib_face_recognition_resnet_model_v1.dat`（约 21MB，特征提取）
> 模型文件可网上下载（dlib 官方），不可商用风险低。

## 六、实施步骤（分阶段，每阶段可独立验证）

| 阶段 | 内容 | 验收标准 |
|------|------|---------|
| **1. 环境搭建** | 下载/编译 OpenCV、Dlib；.pro 配置链接；模型文件放入 | 空工程可调用 OpenCV 打开摄像头 |
| **2. 摄像头预览** | 在"考勤打卡"界面显示实时视频流（工作线程 + QLabel） | 界面流畅显示摄像头画面 |
| **3. 人脸检测+画框** | 每帧检测人脸，在视频上画绿色矩形框 | 正对摄像头时框住人脸 |

| **5. 打卡识别** | 员工打卡界面比对识别 → 调用现有打卡逻辑 | 识别正确员工并写入考勤记录 |
| **6. 体验优化** | 活体检测（眨眼/转头）、阈值调优、多人脸处理、光线自适应、错误提示 | 准确率 > 90%，防照片攻击 |

## 七、风险与注意事项

1. **准确率影响因素**：光线（建议顺光）、角度（正面）、遮挡（口罩需先摘除）、摄像头清晰度
2. **活体检测**：基础方案容易被照片/视频欺骗，阶段 6 可加眨眼检测（OpenCV 或 Dlib 眼部纵横比 EAR）
3. **性能**：Dlib HOG 检测在低端机约 100-300ms/帧 → 建议检测间隔 300ms，避免每帧都跑
4. **模型文件体积**：两个 .dat 约 80MB，发布时要一起打包
5. **数据迁移**：已有 employee 表员工需补录人脸（管理员逐人录入，或批量导入）
6. **与现有打卡规则无缝衔接**：识别成功后走 `getAttendanceRule()` + `getTodayAttendanceStatus()` + `insertAttendance()`，迟到/早退/去重逻辑完全复用
