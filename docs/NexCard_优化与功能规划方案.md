## 四、人脸识别打卡专项方案（重点）

### 4.1 场景与目标

现状考勤**完全依赖刷卡**：任何人拿到卡即可打卡，存在代打卡、丢卡冒用、忘卡无法打卡等问题。
目标：**"刷卡定位 + 人脸 1:1 校验"双因子打卡**——刷卡快速定位到具体员工，摄像头人脸比对确认为本人后写入考勤。

> 为什么选"刷卡+人脸"而不是纯人脸 1:N？
> 1. 1:1 比对速度更快、误识率极低（双胞胎/相似脸问题大幅缓解）；
> 2. 与现有刷卡硬件和员工表结构无缝衔接；
> 3. 1:N 需要全量特征检索，N 大时耗时长且需要专门的人脸库索引。

### 4.2 技术选型对比（本地离线为主）

| 方案 | 检测 | 特征提取 | 优点 | 缺点 | 适用 |
|------|------|----------|------|------|------|
| **A. OpenCV DNN + 开源 ONNX 模型**（推荐） | cv::FaceDetectorYN（YuNet，约 200KB） | ArcFace/SFace 的 ONNX 模型（MobileNet 版约 10~30MB，ResNet 版约 100~250MB） | 完全开源免费、离线、可定制、Windows 集成好 | 需自行下载模型、推理需 ONNX Runtime | 学习/毕设/自研 |
| **B. 虹软 ArcFace SDK** | 内置 FD/FT/FR | 512 维 float 特征 | 免费离线、C++ API 简单、文档全、有活体模块 | 免费版有试用期，商用需购买授权 | 产品化最快 |
| **C. Dlib** | CNN 检测 | resnet10 128 维 | 经典、教程多 | 检测慢、模型大（约 100MB） | 一般不建议 |
| D. 云 API（百度/腾讯云） | - | - | 免本地部署 | 需联网、按量付费、隐私合规风险、考勤实时性差 | 不建议本地考勤用 |

**推荐**：本项目选择 **方案 A**（OpenCV + YuNet 检测 + ArcFace MobileFaceNet/ResNet ONNX 特征 + ONNX Runtime 推理），成本为零、可控性强。

### 4.4 数据库扩展

```sql
-- 方式一：employee 表扩展（推荐，1 人 1 特征）
ALTER TABLE employee ADD COLUMN face_feature BLOB;      -- 512×4=2KB float 数组
ALTER TABLE employee ADD COLUMN face_registered INTEGER DEFAULT 0;  -- 是否已录入

-- 方式二：独立人脸表（支持 1 人多张特征，便于重注册历史）
CREATE TABLE IF NOT EXISTS face_feature (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    card TEXT NOT NULL,
    feature BLOB NOT NULL,        -- 特征向量二进制
    reg_time TEXT NOT NULL,       -- 录入时间
    FOREIGN KEY(card) REFERENCES employee(card)
);
```

> 注意：SQLite 迁移建议随 `schema_version` 机制（见 P1-10）一并做，避免直接 ALTER 老库失败。

### 4.5 核心业务流程

**人脸注册流程（管理端）**：
```
管理员进入"人脸录入" → 刷卡定位员工 → 摄像头采集 → 人脸质量检测
（清晰度/角度/光照）→ 提取特征 → 活体检测通过 → 存入 face_feature → 提示成功
```

**打卡流程（员工端，改造后）**：
```
① 刷卡 → 卡号合法 → 定位员工 → 从库中取出其 face_feature
② 摄像头取帧 → 人脸检测 → 未检测到人脸则提示"请正视摄像头"并重试
③ 特征提取 → 与库中特征余弦相似度比对
④ 相似度 ≥ 阈值 → 活体检测通过 → insertAttendance(签到/签退) → 语音/弹窗反馈
⑤ 相似度 < 阈值 或 活体失败 → 提示重试；连续失败 N 次 → 转管理员人工处理
⑥ 未录入人脸的员工 → 提示先到管理员处录入，允许降级为纯刷卡（可配置）
```

### 4.6 准备工作清单（动手前需要备齐）

**① 硬件**
- [ ] USB 摄像头：UVC 免驱、720p 以上（1080p 更佳）、支持 MJPEG 流；考勤机位距离 0.5~1.5m，水平视角 ≥ 60°
- [ ] 环境光照：机位正面均匀补光，避免逆光/强背光（可后期加软光板）
- [ ] 运行主机：普通 x86 即可（ArcFace Mobile 推理 < 50ms/帧，无需 GPU）

**② 软件依赖与工程改动**
- [ ] Qt Multimedia 模块：`.pro` 增加 `QT += multimedia`（QCamera 取流）；或直接用 OpenCV `VideoCapture`
- [ ] OpenCV（≥ 4.8，需包含 dnn 模块；用预编译版或 vcpkg）
- [ ] ONNX Runtime（CPU 版即可）+ 头文件/库路径配置（INCLUDEPATH / LIBS）
- [ ] 第三方模型文件（离线放置到资源/模型目录）：
  - 人脸检测：`face_detection_yunet_2023mar.onnx`（OpenCV 官方，约 230KB）
  - 特征提取：ArcFace MobileFaceNet（约 12MB，精度够用）/ W600K-ResNet50（约 250MB，精度更高）
- [ ] 人脸数据合规：特征仅存本地、不联网上传；按《个人信息保护法》及人脸识别技术应用相关规定，向员工告知并取得单独同意

**③ 算法阈值与测试集**
- [ ] 余弦相似度阈值标定（建议 0.5~0.7 区间做真/假阳性实验后确定）
- [ ] 测试用例：光照变化、戴眼镜/口罩（口罩时建议关闭人脸校验或提示摘除）、角度 ±30°、多员工串扰
- [ ] 活体检测方案（防照片/视频攻击）：眨眼检测（EAR 算法，开源实现多）或静默活体模型

**④ 与现有代码的接入点**
- [ ] `myserial.cpp` getCard 已发出 cardIdReceived → 打卡页已有卡号，无需改动串口层
- [ ] `mysql.cpp` 新增 `saveFaceFeature(card, feature)` / `getFaceFeature(card)` 两个接口
- [ ] `employeeattendancewidget.cpp` 打卡按钮流程中插入"人脸校验"步骤
- [ ] 管理端菜单新增"人脸录入"入口（adminpagewidget 树形菜单 + 懒加载页面）

### 4.8 风险与对策

| 风险 | 对策 |
|------|------|
| 光照变化/逆光导致识别率下降 | 补光 + 多角度注册 + 阈值下调重试提示 |
| 双胞胎/高度相似脸 | 刷卡定位后 1:1 比对（仅比对 1 人），误识率极低 |
| 化妆/发型/年龄变化 | 定期重注册；注册界面支持覆盖更新特征 |
| 照片/视频攻击 | 活体检测（眨眼/静默活体）；重要场景可加管理员确认 |
| 人脸数据隐私合规 | 特征本地存储 + 加密（QCAES 或系统 DPAPI）、告知同意、不联网 |
| 摄像头被占用/损坏 | 打卡流程检测摄像头打开失败时降级为纯刷卡并提示 |
